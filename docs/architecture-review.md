## 1. 项目定位

面向**合规自动化渗透测试**的安全评估 Agent（Go 1.26 后端 + React/Electron 前端 + Docker 部署）。核心设计哲学（用户定调）：

1. **观测-推理循环**：工具只做零判定观测（HTTP 原语拿原始响应），结论一律由模型基于证据得出——"不要把模型的思维固化死"
2. **黑板仅作存储**：跨会话结论笔记 + 证据回链，不是推理引擎（用户明确否决了黑板调度算法）
3. 检测/验证/凭据测试在范围内；exploitation/后渗透由 managed bundle 承担（平台边界）

评测环境：TSec Benchmark（63 题，easy 9 / medium 25 / hard 29，总分 23,000）。API 契约：list/start/submit/close/hint 五操作，BENCHMARK_TOKEN 头认证，3 容器并发上限，VPN 内网直连靶场。

## 2. 当前架构（GateMesh v1 落地形态）

### 2.1 分层总览

```
L4 知识层   79 SKILL.md（Claude-Red，MIT）→ 蒸馏为 1,889 配方节点
            12 维攻击面位掩码（surf/web/waf/inject/auth/file/rce/cloud/net/crypto/mobile/recon）
            共轭超图匹配：实体状态 ∩ 前置条件 ≥70% 唤醒，注入 ≤1.5K 配方切片
L3 认知纪律 观测蒸馏（原始响应 4KB→600B 结构化摘要，红线：原文不进上下文）
            三级模型路由（L0 反射零 LLM / L1 战术 glm-5.3-flash / L2 旗舰卡门唤醒）
L2 四门     Scope（OBSERVE+EXECUTE 双路出站白名单，infrastructure 分类拒绝）
            Evidence（E2 Tentative→E3 Verified，ACTION:VERIFY 重放差分晋升）
            Progress（IGR 停滞检测：5 轮黑板零新增→强制掉头；DONE 驳回门）
            Budget（driver 全局轮次硬顶 + 子循环总预算 + OURO_TACTIC_MODEL 路由）
L1 传送带   ACTION:BENCH 五操作零 LLM 直调平台（Go http，蒸馏输出，审计落盘）
L0 状态脊   eventlog SQLite WAL 唯一真值 · 幂等四阶段租约 · 毒丸隔离（崩2次拉黑换工具）
            子循环注册表持久化（subloops.jsonl，重启恢复）
```

### 2.2 执行单元

- **父循环（编排者）**：driver 驱动的回合制对话。每轮注入观测事实（平台对账+子循环状态+编排缺口检测），模型决策，ACTION 文本协议执行
- **子循环（SPAWN）**：后端 goroutine 自治观测-推理循环。独立上下文、40 轮预算、每 5 轮 PROGRESS 摘要、黑板种子（相关结论+配方超图命中）、完成通知注入父会话
- **通信介质**：黑板（blackboard.jsonl，stateMu 串行）+ observations.jsonl + 完成通知

### 2.3 动作协议（当前形态，也是问题核心之一）

模型以文本行输出动作，后端解析执行：
```
ACTION:OBSERVE <url> [JSON spec]     # 观测原语，{{env:VAR}} 占位符展开
ACTION:BENCH <op> [args]             # 平台传送带（list/start/submit/close/hint）
ACTION:SPAWN <名字> : <目标>          # 派子循环
ACTION:COLLECT [<名字>]              # 收割子循环状态
ACTION:BLACKBOARD <结论>             # 结论落黑板（obs-ID 回链）
ACTION:VERIFY <obs-id> <信号>        # E2→E3 差分晋升
ACTION:EXECUTE CONFIRMED: <命令>     # shell（过 egress gate）
ACTION:READ/WRITE/LIST/SEARCH/...    # 工作区文件操作
```

### 2.4 韧性机制（实战验证有效）

- provider 瞬态重试（3s/9s 退避，TLS 超时/断连类错误）
- driver 失败感知（模型调用失败不推进轮次，退避重发同消息）
- 崩溃恢复（restart=always + workspace bootstrap + journal 持久）
- 多行 JSON spec 合并（coalesceActionLines 括号平衡）、智能引号归一化

## 3. 实战结果与失败模式（33 场实测，v16→v27 十一个版本）

### 3.1 结果摘要

- **成功解题**：2 题（e1-01、e1-02，各 250 分，v8 时代 flash 模型）
- **架构能力验证**：传送带秒级响应✅ 黑板沉淀✅ 容器管理（3/3 满载）✅ 网络韧性✅ 超图命中✅
- **核心卡点**：v19-v27（换旗舰 glm-5.3 后）**零新增解题**——全部卡在"编排执行"环节

### 3.2 失败模式分类（按频率与危害排序）

#### FM-1：分析瘫痪（最高优先级，未解决）

**现象**：模型每轮产出 7-8K 字符深度推理，动作行被挤掉或延迟。v21 实测：73 条消息、15+ 轮、idle=14，SPAWN 目标写了 30+ 条消息从未执行。

**已试修复及效果**：
| 修复 | 效果 |
|---|---|
| 自主性契约第 6 条（动作必须在场） | ⚠️ 动作有了但仍在分析后（位置 1500+ 字符） |
| action-first（动作行开头） | ⚠️ 部分生效，长分析仍在后 |
| 产出通牒（4 轮零实质产出→强制三选一） | ⚠️ 触发但被模型"审议通牒本身"消化 |
| token 硬帽（driver 管道 64-96） | ✅ 对 driver 回显有效（但那是架构自己跟自己说话） |

**理论诊断**：glm-5.3 的 reasoning_content 思考通道与回复体不分离（Anthropic 文中 extended thinking 是显式通道）。我们的提示词约束管不住模型在回复体里写论文。

#### FM-2：格式执行失败（已大部分修复）

占位符照抄（`<name>`/`<flag值>`/`{{env:}}` 误伤）、缺 ACTION: 前缀、JSON 中智能引号。修复链：守卫×3 版（黑名单→白名单→只查名字位）、引号归一化、verbatim 回显提示。**残留**：守卫仍有误伤空间，每新增语法就要新增守卫——治标。

#### FM-3：重复获取已有信息

模型反复 OBSERVE 已观测目标 / READ 全量题单（2 万字进上下文）。已修：重复观测警告、BENCH list 加活跃题详情。**残留**：警告是劝不是禁，READ 全文仍是唯一信息获取方式。

#### FM-4：指令二义性死锁

"微任务教学"与"整题目标"冲突→模型哲学审议"怎么拆才合规"。已修：双许可。**教训**：教学措辞的语义边界必须显式，否则模型会把它当作需要满足的约束去优化。

#### FM-5：环境与进程

网络抖动（~40 次，多层重试已驯服）、Docker/agent 死亡（restart+bootstrap 已修）、pip 构建层（离线 wheel 根治）。

### 3.3 信息经济学实测（会话记录统计）

```
输入 token 构成：~60% 已见信息重复 / ~25% 系统提示 / ~15% 新证据
输出 token 构成：~70% 无行动价值分析 / ~20% 格式开销 / ~10% 动作
有效信息密度 < 15%
```

### 3.4 关键不对称发现

**子循环质量 >> 父循环质量**。子循环实测：正确识别 DVWA、系统设计绕过策略、PROGRESS 摘要纪律好、黑板沉淀规范。父循环：分析瘫痪、格式失败、重复获取全集中在它身上。**编排是模型最不擅长的事，侦察解题反而是强项**。

## 4. 理论推导（GateMesh v2 方向）

### 4.1 三个结构性判断

1. **决策-执行耦合是错的**：模型必须输出正确格式文本才能推进 → 认知优势被格式纪律拖累，架构可靠性被等待模型拖累。Anthropic 的隐含答案：tool_use 结构化调用（模型选工具，架构管格式）。我们的 ACTION: 文本协议本身是古董
2. **黑板缺查询接口**：有存储没检索 → 模型只能 READ 全文。需要谓词查询原语
3. **委派不对称律**：编排节奏归架构，委派质量归模型，执行格式归协议——各自最优化，不再互相拖累

### 4.2 v2 蓝图（已推导未实现）

- **L5 意图层**：IntentGraph——chat API 加 `responseMode:"intent"`，模型返回 `{"intent":"spawn","target":"e1-01","goal":"..."}` 结构化意图，后端直接执行。格式失败类问题整类消灭
- **L3 查询式黑板**：`ACTION:QUERY <谓词>`（`kind=conclusion host=10.0.x.x` / `contains flag{`）——信息密度 15%→60%+
- **L4 已落地**（v25 形态）：硬流水线节奏 + 模型一行决策 + 默认策略兜底

### 4.3 待验证假设（下个靶场窗口）

| 假设 | 实验 | 指标 |
|---|---|---|
| 意图协议消灭格式失败 | intent vs ACTION-text | 格式错误/百轮 |
| 查询黑板提升密度 | QUERY vs READ | 新信息占比 |
| 委派不对称提升吞吐 | v27 vs v28 | 首题时间、题/小时 |

## 5. 给外援的具体问题

1. **FM-1 的根治**：在回复体与思考通道不分离的模型（GLM 系）上，如何可靠压制"分析淹没动作"？我们考虑过：意图协议（结构化输出）、强截断（后端只取动作行丢弃其余——丢掉的推理是否浪费？）、双通道生成（两次调用：一次纯分析一次纯动作——成本翻倍）。业界有无第四条路？
2. **意图协议的 schema 设计**：spawn/observe/submit 的意图 JSON 需要多严格？自由 goal 字段与结构化字段的边界在哪？
3. **父循环的存废**：数据支持"子循环强、父循环弱"——是否应该彻底删除父循环对话，driver 全机械编排 + 模型只在子循环内出现？还是会丢失 Anthropic 强调的 lead agent 综合判断价值？
4. **黑板查询原语的语义**：谓词该多富（key=value/全文/时间窗）？有没有业界先例（记忆系统的检索接口设计）？
5. **评测方法论**：33 场数据够不够做架构 A/B？Anthropic 用 20 query 起步——我们单变量隔离（只改一层）的实验设计是否正确？
